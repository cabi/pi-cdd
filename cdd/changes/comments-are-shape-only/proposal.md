# comments-are-shape-only

## Why

The harness's source comments have accumulated a second, hand-maintained index of the corpus: pointer comments cite ADRs, PFs, and commit ids; file headers carry lessons and rationale the corpus already owns; and scripts/spec-drift.mjs keeps a prose check index that has already drifted twice (a cold R3 caught the missing L4 tag; this change's audit found it now also missing the emitted [G] and [H] tags). These comments are the same disease as spec markers in source (rule 10) in shorter form: a reverse index — static, unverified, silently rotting — while the corpus already indexes code forward (Code: globs, pins) with enforcement, and the doors route editors to the corpus at edit time.

## What Changes

- ADR-0012 records the decision: comments may only describe the code they sit in — the module's/function's contract, the algorithm's reading order, observed caller behavior. Banned in comments: corpus routing (ADR/PF/spec/change/commit ids of any form), WHY-prose (lessons, history, rationale), WHAT-restating, hand-maintained indexes.
- A behavior-preserving sweep enacts it: pointer comments and corpus-id citations deleted from index.ts, lib/*.{mjs,ts}, scripts/*.mjs, .githooks/* (with the PRE_COMMIT/COMMIT_MSG template strings in lib/templates.mjs edited in lockstep); file-header WHY-banners and silent-exec guards compressed to shape-only text; lesson-rationale blocks in lib/validate.mjs and lib/store.mjs deleted (index.ts's fill-in rewrite rationale stays — observed caller behavior); the spec-drift.mjs header rewritten shape-only with a machine-readable `// Checks:` line; door copies regenerated byte-identically through writeDoorScripts.
- Test comments: spec-heading-citation banners and corpus-id/lesson prose stripped from tests/, keeping every test-local check-id name (the failure output names the id; the spec greps forward).
- Three suite pins: two red-first — tests/acceptance/comment-law.test.js scans comment text of index.ts, lib/, scripts/, .githooks for corpus-id patterns and reports zero (with a committed synthetic fixture proving the scanner can fail: names file, line, pattern, exits non-zero), and tests/acceptance/guard-header-index.test.js asserts the guard header's `// Checks:` line is set-equal to the tags the script actually emits (with a synthetic unindexed-tag exercise) — plus tests/acceptance/comment-shape-adr.test.js, an existence pin asserting ADR-0012 is on disk, status accepted, carrying the rule, both allowances, and the drift evidence.
- PF-22 minted from the handshake audit: ADR-0004's code glob is stale (lib/context.ts), leaving the ambient-injection decision with empty A1 ownership.

## Solutions Considered

- comment law: existing rule 10 (no spec markers in source) already bans traceability markers but says nothing about pointer comments, WHY-prose, or hand-maintained indexes — adopted as the principle this change extends, rejected as sufficient alone because it names no comment law and pins nothing.
- header index: generating the spec-drift.mjs header from the checks table at build time — rejected: the file is a zero-dependency door script with no build step; a generated header would need a codegen lane the repo does not have. The set-equality pin (adopted) gives the same rot-loudness with no new moving parts; the header stays hand-written but can no longer silently drift.
- enforcement: extending cdd/scripts/spec-drift.mjs with a comment-law check — rejected for this change: door scripts run on every commit in every adopting repo; teaching the guard comment semantics (a string-aware scanner) belongs to a deliberate guard change if ever needed, while an acceptance pin runs with the project's own tests where the scanner's false-positive risk is reviewed as code.

## Non-Goals

- No change to any code behavior: every edit is comment text; strings, error messages, scaffold content, and rendered law text keep their corpus references (they are behavior or corpus data, not comments).
- No enforcement pin over tests/ or cdd/scripts/ copies: tests keep check-ids and fixture ids by allowance; the door copies are pinned byte-identical by the existing P5 checks. The tests/ scenario-heading-prose ban is enacted once by the sweep and rests as convention (ADR-0012's allowance keeps check-ids), not on a pin.
- No rule-N/door-N pattern in the pin: natural-language collision-prone (grammar-law literally renders rule text); swept where they route, unpinned by decision.
- No fix for PF-22 inside this change (corpus-index cleanup is its own change); no ADR glob restatements; no new guard checks.

## Decisions followed

ADR-0001 (zero-dependency Node tooling — sweep keeps scripts/*.mjs stdlib-only), ADR-0002 (harness is the counterparty — index.ts door-1 mirror comments swept, behavior untouched), ADR-0003 (plain markdown store — lib/store.mjs header compressed to shape, breadcrumb deleted), ADR-0006 (feature-block consolidation — grammar-law/validate citation comments swept; the fence law's ADR-0006 references inside error strings and scaffold templates are data, kept), ADR-0007 (law behind every door — door-copy regeneration through writeDoorScripts keeps the copies byte-identical), ADR-0008 (advisory findings — review-point comments in templates/instructions/context/help are rendered text, kept; code comments swept), ADR-0009 (single-source loop law — loop-law.mjs header compressed to shape; the law facts themselves are strings, kept), ADR-0010 (reviewer independence is loop law — loop-law.mjs header banner compressed to shape; the law facts are module strings, kept), ADR-0011 (ticks are claims — every tick in this change cites an exact command). ADR-0004 (ambient injection) is not cited as followed: its code glob claims lib/context.ts, a path that does not exist — minted as PF-22; the lib/context.mjs header comment citing it is swept as corpus routing regardless. ADR-0012 is this change's own decision, drafted accepted under the sponsor's delegated authority; it is cited here so the A1 door finds it in this change's docs once its code globs overlap the delta's claimed files.
