- T1 YES — spans two capability seams: gherkin (law predicate, guard L1, createChange) and extension (rendering the warning in `/cdd-new` and the `new` tool op). Two delta specs, one proposal.
- T2 NO — no new architecture: (a) spawns the existing guard script as the single source of door-3 truth (director steer; aligns with ADR-0009's single-source direction — no in-process mirror); (b) adds a grammar predicate where grammar lives (ADR-0007). No new dependency.
- T3 YES — new shared field on an existing seam: `createChange` returns `preexistingRed: string[]` (always present when `ok`; empty = green; one entry per guard issue line, verbatim). Extension renders it; gherkin tests pin its content.
- T4 YES — the guard's L1 "every pin resolves" invariant gains a scoped exception: placeholder pins in open-delta specs are skipped (never in living specs; draft validation still counts placeholders unfilled; strict still refuses them at archive). Red window closes at draft-green at the latest; the skip is always reported, never silent.
- T5 NO — single runner, dedicated branch `green-start`, no other open changes.

Design (for T1/T3/T4):

1. **Detection = the real guard.** `createChange` runs `process.execPath cdd/scripts/spec-drift.mjs` (full scan, `cwd` = store root, stdout AND stderr captured, `execFileSync`, 60 s timeout) BEFORE writing any artifact. Exit 0 → `preexistingRed: []`. Exit non-zero → the guard's stderr issue lines (the indented, bracket-tagged lines), verbatim, in order; summary line and stdout are not findings. Exit non-zero with NO issue lines = guard aborted → exactly 1 entry "guard could not complete: <abort message>". Missing script / spawn failure → exactly 1 entry "guard could not run: …" (still non-blocking). Whatever the guard reports, we report — no filtering, no second law.
2. **Placeholder law.** `isPlaceholderPin(pin)` in the law module `scripts/law.mjs` (`LAW_VERSION` 1→2; store copies `cdd/scripts/law.mjs` + `cdd/scripts/spec-drift.mjs` regenerated byte-identical, verified by an acceptance scenario): true when the pin path contains the scaffold's placeholder marker — the angle-bracket form of `scenario` or `name`, the exact token family `lib/validate.mjs` already treats as unfilled, so the guard and the draft door agree; any other angle-bracket shape stays L1-red (conservative direction — the guard never silently greens an unrecognized token). Guard L1: for pins from specs under `cdd/changes/*/specs/`, placeholder pins are skipped and counted per change; after the verdict the guard prints one informational line per change to stdout ("N placeholder pin(s) skipped in open delta <name> — expected until implementation"). Living specs keep full L1 strictness. Draft validation (placeholders unfilled) and strict validation (unresolved pins) are untouched.
3. **Warning is advisory.** `cdd new` proceeds regardless; both surfaces render "pre-existing red at change start — this change did not cause it" plus the findings and a hint to fix or knowingly accept.
4. No ADR drafted or amended: tolerating `<...>` template pins during the scaffold window clarifies ADR-0006 (pin dialect) and ADR-0007 (grammar owns law); invoking the guard adds no second implementation (ADR-0009 untouched). Skip recorded at 4.2.
